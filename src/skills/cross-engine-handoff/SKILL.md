# Strict Antigravity handoff

Load the reliable-maker-control skill for write, delegated, resumed or multi-step
work. Collaboration never weakens that skill, Contract, running Attempt, real
Binding, guarded tool restrictions, current content hashes or required checks.

Use the installed `.gemini/scripts/invoke-antigravity-handoff.ps1` adapter.
It shares the task format with Codex but fixes the producer to Antigravity.
Read the task, preserve its ID and required checks, Acquire with the observed
revision, and use the returned token only as a coordination identifier.

Handoff requires `-NativeTaskRoot` and exact `-DecisionPath`. The native logical
task ID must match the shared ID. The adapter calls the existing governed audit,
which rechecks the original Completion Gate and current evidence. Missing or stale
evidence blocks Handoff. `Release` can stop work without declaring acceptance.
For incomplete work, stop old processes and Release with a NextAction, then let
Codex Acquire the current revision. This preserves strict policy and all failed
or stale evidence; it is partial takeover, not an accepted completion.
Do not use the generic shared helper to bypass this strict adapter.

Codex plans and evidence are context only. Never map their lightweight validation
or shared `reference-only` records to a canonical Envelope, Post or verified gate.
Even when Codex becomes reviewer, Antigravity-origin work keeps strong validation.
Do not downgrade guarded to observe, invent checker identity, or alter old failures.

One cooperating writer per checkout. Stop old processes before releasing; expired
leases do not authorize takeover. Separate worktrees for concurrent edits.
This protocol is not an OS sandbox, scheduler, native hook, or permission grant.
