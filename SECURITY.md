# Security and reporting boundaries

This independent project is a reliability/governance layer, not a complete OS
sandbox or a verified identity system. Same-user arbitrary execution, unobserved
tools and host filesystem races remain outside its proven isolation boundary.
Never infer permission from a role name, hash, shared lease or successful tool label.

Do not use the current scoped baseline for production credentials, irreversible
migrations, payments or unattended publication. Preserve native approval boundaries.
Antigravity guarded mode denies opaque terminal/subagent execution; never silently
downgrade the mode to complete a task. Strict isolation is currently unavailable.

Do not publish auth/config instances, tokens, raw transcripts, runtime databases,
private screenshots or identifiable session records in issues or commits. Use a
minimal synthetic reproducer. Historical local evidence and rollback backups stay
outside the publishable snapshot. A private repository is not a substitute for
secret hygiene.

There is no configured private vulnerability intake endpoint in this snapshot.
For a suspected sensitive issue, arrange a private channel with the maintainer
before sending details; do not post exploit material or secrets in a public issue.
