# Architecture: Reliable Maker Control Plane

## Layers And Trust Boundaries

```text
source repository
  -> isolated verification/staging
  -> optional transactional runtime install

$env:USERPROFILE\.gemini
  AGENTS.md / GEMINI.md / skills / agents / scripts / schemas / harness-evals
  harness-state\
    .gemini-private
    jobs\ failures\ verification\ evals\ learning\

forbidden source state
  credentials / conversations / brain / databases / caches / private state
```

Antigravity Desktop v3 adds a separate official customization surface:

```text
source:  src/desktop-hooks/antigravity-reliable-control
runtime: $env:USERPROFILE\.gemini\config\plugins\antigravity-reliable-control
events:  $env:USERPROFILE\.gemini\harness-state\hook-probe
```

The first Hook is observe-only and fail-open. It is not yet a mutation gate.

`.gemini-private` is a marker file, never the private-state directory itself.
The containing directory is excluded from extraction and overwrite.

## Truth Registry

Capabilities are described across three independent dimensions:

- implementation: `declared`, `implemented`, or `verified`;
- availability: `unverified`, `available`, or `unavailable`;
- enforcement: `native-enforced`, `script-enforced`, `human-enforced`,
  `policy-only`, or `unverified`.

Markdown cannot prove native enforcement. `ask_question`, Planning Mode,
background tasks, scheduling, reactive wakeup, subagents, and model routing
remain unverified until a live Antigravity canary produces evidence.

## Execution Flow

```text
capability probe
  -> governed TaskRoot registry
  -> task contract
  -> scoped maker execution
  -> mutation/tool evidence
  -> verification envelope
  -> independent checker
  -> completion gate
  -> user approval for high-risk effects
```

### Task Contract

The contract records objective, non-goals, allowed and denied paths, file and
line budgets, dependency and architecture policy, required checks, and approval
triggers. Scope expansion fails closed.

`new-governed-task.ps1` binds the contract to one logical TaskRoot. Starting a
replacement root for the same logical task requires the prior root and a
transition reason; silent root replacement is rejected by the registry.
The registry also hashes normalized objective, non-goals, scope, checks, and
budgets into `task_intent_sha256`. Renaming the LogicalTaskId does not evade an
already-active equivalent intent. Registry roots carry `.gemini-private`.

Scope has two deliberately different observations: caller-declared
`pre_write_declared` checks happen before mutation, while filesystem-derived
`post_write_observed` checks audit actual changes afterward. The latter is not
native interception.

### Job State

Jobs transition monotonically through drafted, approved, running, checking,
waiting approval, and a terminal verified/blocked/stopped state. Retries create
new attempts; the same logical side effect retains its idempotency key.

### Verification

The envelope records safe hashes and real child-process evidence. A nonzero
exit, timeout, missing required path, zero collected tests, changed protected
path, or stale input fails verification. The completion gate rechecks current
source, tests, protected paths, envelope hash, and workspace fingerprint.

Completion claims are generated by `new-completion-claim.ps1`. Producer hashes
support deterministic source-version auditing but do not prove actor identity
or provide a trusted external checker boundary.

### Authority

- Maker changes only task-contract-owned product paths.
- Test Author changes tests but cannot approve completion.
- Test Runner executes checks without editing source or tests.
- Reviewer reads the actual diff and evidence but cannot issue `verified`.
- The source-only Completion Gate validates evidence but remains `checking`;
  only a future externally attested gate may issue `verified`.
- User is the only approval authority for scope expansion, destructive effects,
  migrations, merge, deployment, and publication.

## Context And Lifecycle Policies

`src/AGENTS.md` stays under 80 lines. In v2.1, the globally injected
`GEMINI.md` is a small router. The five lifecycle policies
live in `skills/reliable-maker-control/SKILL.md` and are read only for qualifying
work. This conditional loading remains `policy-only` until a restart canary
proves that Antigravity actually follows the router.

IAS is advisory. Objective scope, state transitions, progress evidence,
fingerprints, checker independence, and completion-gate results control work.

## Behavioral Evals

The deterministic suite covers phantom capabilities, expired component state,
scope overreach, budget violations, monotonic job transitions, workspace
fingerprints, idempotent command execution, real exits, zero-test collection,
stale inputs, timeout process trees, maker self-verification, and independent
completion.

Attempt truth is stored separately from job state. The completion report is a
deterministic projection of the ledger, and the completion gate compares the
report with the original ledger before accepting evidence as `checking`.
